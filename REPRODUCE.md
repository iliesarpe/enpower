# Reproducing the paper

**[Back to the README](README.md)** | **[Implementation notes](docs/IMPLEMENTATION.md)**

This guide describes how to reproduce every experiment of the paper **"Exact power indices for
plurality-voting ensembles"**. All experiments are run with the script `./reproduce.sh` from the root
of the repository. Each step skips the computations whose output already exists, so rerunning an
interrupted command resumes it.

```sh
./reproduce.sh all                  # all the steps below, in order
./reproduce.sh container            # build the Apptainer image enpower.sif
./reproduce.sh build                # compile cpp/solver and cpp/check
./reproduce.sh data                 # download the datasets and CLIP into data/
./reproduce.sh check                # test the C++ algorithms against brute force
./reproduce.sh smoke                # a small end-to-end run to test the setup
./reproduce.sh run    EXP|all       # all the cells of an experiment, sequentially, on the local machine
./reproduce.sh submit EXP|all       # the same cells as SLURM job arrays
./reproduce.sh report EXP|all       # figures and tables, written to results/
```

`EXP` is one of `splits`, `mc`, `clip`, `synth` (and `tables` for `report`).

## Requirements

- [Apptainer](https://apptainer.org/), to build and run the image `container/enpower.def`. The image
  contains `g++`, Python 3.10 with scikit-learn, PyTorch (CPU) and CLIP, and TeX Live for the figures.
  Every command of `reproduce.sh` runs inside the image, with the repository mounted at `/workspace`.
  The variable `ENPOWER_SIF` specifies a different image.
- About 3 GB of disk space for `data/`, and network access for `./reproduce.sh data`. No other step
  requires network access.
- For `submit`: SLURM. The partition and the account of the cluster are set through the environment
  (`export SBATCH_PARTITION=... SBATCH_ACCOUNT=...`). The variable `MAX_RUNNING` (default 16) limits
  the number of array jobs that run concurrently.

**Without Apptainer**, set `ENPOWER_NO_CONTAINER=1` to run all commands on the host. The host then
requires `g++` (C++17), a LaTeX installation with the packages `libertine`, `newtx` and `zi4`, and a
Python installation with the packages of `container/environment.yml`, together with `torch`,
`torchvision` and `git+https://github.com/openai/CLIP.git`. The variable `PYTHON` specifies the
Python interpreter, for example:

```sh
ENPOWER_NO_CONTAINER=1 PYTHON=python3.10 ./reproduce.sh smoke
```

## Experiments

Each experiment consists of independent *cells*. `scripts/cell.sh EXP count` prints the number of
cells, and `scripts/cell.sh EXP i` runs cell `i`. The command `run` executes the cells sequentially on
the local machine. The command `submit` executes them as a SLURM job array (`slurm/EXP.slurm`), after
a job that compiles the C++ library and downloads the datasets. The variable `CELLS_FILTER` restricts
the cells, for example
`CELLS_FILTER="--seeds 100 --datasets credit-g" ./reproduce.sh run splits`.

**`splits`**: binary classification over five random splits (seeds 100–104). There are 90 cells
(5 seeds × 6 datasets × 3 ensembles). Each cell
1. trains the ensemble of the split and runs Tr-PS and Tr-MLE (`python/train_binary.py`);
2. runs ENPOWER<sub>B</sub>, WMG and ISCG in C++ (`enpower.py splits run`);
3. runs MC-β and MC-φ, the Monte-Carlo approximations with sample size n², in C++
   (`enpower.py splits mc`).

The raw outputs are written to `outputs/splits/seed<s>/`.

**`mc`**: runtime for multiclass classification over five random splits. There are 30 cells
(5 seeds × {CNAE-9, Covertype} × 3 ensembles). Each cell trains the ensemble on the original labels
(`python/train_multiclass.py`), then measures the runtime of ENPOWER<sub>MC</sub>-β,
ENPOWER<sub>MC</sub>-φ and ENPOWER<sub>MC</sub>-φ++ in C++ (`enpower.py mc run`). The raw outputs
are written to `outputs/mc_splits/seed<s>/`.

**`clip`**: prompt ensembling of CLIP ViT-B/32 with 22 prompt templates on CIFAR-100, ImageNet-A and
Oxford-IIIT Pet, over five random 50/50 splits. The experiment has two stages:
1. `clip-votes`, one cell per dataset (8 CPUs per job on SLURM). Each cell runs CLIP inference to
   obtain the vote of every prompt on every image (`outputs/clip/<dataset>_ViT-B-32_votes.npz`). It
   then runs `python/clip_inference.py` a second time without `--votes-only`, which computes the
   values of the prompts on split 100 with the Python reference implementation, for Tables 9–11.
2. `clip-run`, 15 cells (5 seeds × 3 datasets). Each cell ranks the prompts on D<sub>val</sub> with
   Acc, ENPOWER<sub>MC</sub>-β, ENPOWER<sub>MC</sub>-φ, Tr-PS and Tr-MLE (`enpower.py clip run`).

`report clip` evaluates the top-k sub-ensembles on D<sub>test</sub> with plurality voting and random
tie-breaking.

**Note.** The output of CLIP inference depends on the version of PyTorch, which the image does not
pin. A different version may change a small number of votes, and therefore the reported metrics.

**`synth`**: the synthetic experiments of Sec. G.6. `enpower.py synth gen` writes the deterministic
instances of the grid `cpp/experiments/synth/paper.json` to `data/synth/paper/`. `enpower.py synth
run` measures the runtime on these instances, divided into `SYNTH_SHARDS` shards (16 with `submit`, 1
with `run`). Each run has a timeout of two hours and is repeated 5 times. `SYNTH_CONFIG=small` selects
the smaller grid `cpp/experiments/synth/small.json`.

## Datasets

`./reproduce.sh data` runs `python/download_data.py`, which stores all datasets in `data/`:

| Dataset | Source | Used by |
|---|---|---|
| credit-g (31), bank-marketing (1461), blood-transfusion-service-center (1464), cnae-9 (1468), titanic (40945), Covertype (150) | OpenML, through `sklearn.datasets.fetch_openml`, cached in `data/openml/` | `splits`, `mc` (cnae-9 and Covertype) |
| CIFAR-100 (test split) | torchvision | `clip` |
| Oxford-IIIT Pet (test split) | torchvision | `clip` |
| ImageNet-A | `https://people.eecs.berkeley.edu/~hendrycks/imagenet-a.tar` | `clip` |
| CLIP ViT-B/32 weights | the CLIP package | `clip` |

If the official link of ImageNet-A is unavailable, set `IMAGENET_A_URL` to a mirror of
`imagenet-a.tar`. Alternatively, extract the archive manually so that `data/imagenet-a/` contains its
200 class folders.

The tabular datasets are processed by `load_and_preprocess_data` in `python/train_binary.py` (binary
classification) and `python/train_multiclass.py` (multiclass classification), as described in
Sec. F.2:
1. for binary classification, the most frequent class is the positive class (y = 1) and all other
   classes together form the negative class (y = 0); for multiclass classification, the original
   labels are kept and encoded as 0, …, ℓ−1;
2. numerical features: missing values are set to the median, and the features are standardized to
   zero mean and unit variance;
3. categorical features: missing values are set to the most frequent value, and the features are
   mapped to integers;
4. the data points are split with the seed into 75% for training and 25% held out. After training,
   the held-out 25% is split with the same seed into D<sub>val</sub> (60% of it, i.e., 15% of the
   dataset, used to compute all power indices) and D<sub>test</sub> (40% of it, i.e., 10% of the
   dataset, used for sub-ensemble selection).

The ensembles are a random forest of 50 trees, AdaBoost with 150 base classifiers, and a heterogeneous
voting ensemble of 30 base classifiers (10 decision trees, and 5 each of linear SVMs, logistic
regressions, gradient boosting classifiers and MLPs). The seed of the split is also the random seed of
every base classifier. The ensembles of the binary and of the multiclass experiments are trained
separately, the former on the binarized labels.

The CLIP datasets are split 50/50 into D<sub>val</sub> and D<sub>test</sub> by a random permutation
drawn with the seed (`np.random.seed(s)`).

## Implementation of each method

| Method | Implementation |
|---|---|
| ENPOWER<sub>B</sub>, ENPOWER<sub>MC</sub>-β, ENPOWER<sub>MC</sub>-φ, ENPOWER<sub>MC</sub>-φ++ | C++, `cpp/libs/`, `cpp/solver banzhaf\|shapley` |
| WMG, ISCG | C++, `cpp/libs/baselines.h`, `cpp/solver wmg\|iscg` |
| MC-β, MC-φ | C++, `cpp/libs/sampling.h`, `cpp/solver mc` |
| Tr-PS, Tr-MLE (Troupe) | Python, the unmodified library of Rozemberczki et al. in `python/shapley/` |

`python/shapley_multiclass.py`, `python/banzhaf_multiclass.py` and `python/indices_binary.py` are
reference implementations in Python with exact rational arithmetic. They are used only to validate
the C++ implementation and to compute Tables 9–11:

```sh
python cpp/tools/enpower.py check --points 20 --models 12 --labels 4   # multiclass Shapley: C++ vs Python
python cpp/tools/enpower.py banzhaf --profile 6:6,6,6                  # multiclass Banzhaf: C++ vs Python vs definition
python cpp/tools/enpower.py binary --points 500 --models 30            # binary closed forms: C++ vs Python
```

## Repository layout

```
reproduce.sh            the entry point of this guide
container/              enpower.def (Apptainer image) and environment.yml (Python environment)
scripts/cell.sh         one cell of one experiment; scripts/common.sh runs commands in the image
slurm/                  splits, mc, clip, synth: the SLURM job arrays of the experiments
cpp/                    the C++ library: libs/, main.cpp (cpp/solver), check.cpp (cpp/check)
cpp/tools/enpower.py    runs cpp/solver on the experiments and writes the figures and tables
cpp/experiments/synth/  the grids of the synthetic experiments (paper.json, small.json)
cpp/examples/           a toy input for cpp/solver
python/                 dataset download, ensemble training, CLIP inference, Troupe, reference implementations
data/                   downloaded datasets                  (created, not versioned)
outputs/                raw outputs of the runs              (created, not versioned)
results/                figures and tables of the paper      (created, not versioned)
```

The variables `ENPOWER_OUTPUTS` and `ENPOWER_RESULTS` set the locations of `outputs/` and `results/`.
For `mc` and `clip`, `report EXP --paper DIR` also copies the tables and figures into the directory
`DIR` of a LaTeX paper.

## Running the steps manually

```sh
apptainer build --fakeroot enpower.sif container/enpower.def
alias enp='apptainer exec --bind $PWD:/workspace --pwd /workspace enpower.sif'
enp make -C cpp all check && enp cpp/check
enp python python/download_data.py --only tabular

# one cell of the binary classification experiments, then its report
enp python python/train_binary.py --dataset_id 31 --seed 100 \
    --out-root outputs/splits/seed100 --ensembles random_forest
enp python cpp/tools/enpower.py splits run --seeds 100 --datasets credit-g --ensembles random_forest
enp python cpp/tools/enpower.py splits mc  --seeds 100 --datasets credit-g --ensembles random_forest
enp python cpp/tools/enpower.py splits report --seeds 100 --datasets credit-g --ensembles random_forest
```

`python cpp/tools/enpower.py --help` and `python cpp/tools/enpower.py <command> --help` describe all
subcommands. [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md) describes the C++ library.
